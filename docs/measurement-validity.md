# 测量有效性：如何不被自己的实验骗

面向**接手执行的 agent**。这份文档不讲电机原理，只讲一件事：
**在相信任何一个读数之前，先证明测量链是活的。**

背景：hall6 移植期间，两个 agent 累计至少 7 次因为「测量装置本身是坏的」而得出自信的错误结论，
把负面结果归因给了被测对象。真正的三个根因（低边 `CCR=0`、`RCR=0`、VOUT 滤波电容）
每一个都被这类无效实验掩盖过。技术性的坑见
[`src/firmware/stm32f030/README.md`](../src/firmware/stm32f030/README.md#已知陷阱)，
这里只讲方法。

---

## 1. 通电前自检清单

**每次测量前按顺序过一遍。任何一项不通过，读数一律作废。**

### 1.0 一条命令过完整个自检

```bash
./src/firmware/stm32f030/scripts/board_check.sh          # 停机时
./src/firmware/stm32f030/scripts/board_check.sh --running # 电机运行中
```

全程不 halt（Cortex-M 的内存访问走 DAP），约 4 s。它把下面 1.1~1.7 里能自动化的部分
都做了，并对 VDDA、母线电压、`V_BOOST`、`nFAULT`/`nOTEMP`、PA11、Hall 码、
三路电流零点逐条设了判据，不通过就非零退出。**能用它就不要手写 openocd 命令。**

### 1.1 探头在线

```bash
source src/firmware/stm32f030/scripts/bench_common.sh
require_dap
```

**MCU 由 nanoDAP 供电**（主板 `U5` AMS1117 未焊）。探头掉线的表象是「母线 0.000 A、
所有引脚全平」，和「板子烧了」完全一样。

**空载母线电流基准是约 4 mA**（实测 2026-08-27），不是旧文档里的 6 mA。
差别的来源：12 V 现在还要供 `LM339` 的 `V+`、12 V 指示灯、电荷泵的 `R28` 上拉
和两条分压串，而 MCU 与模拟域走探头的 3.3 V。**0.000 A 说明 12 V 没上**。

### 1.1.1 12 V 缺失时故障线会假装正常

`nFAULT` / `nOTEMP` 的 4.7 kΩ 上拉挂在探头供的 `+3V3` 上，而 `LM339` 的 `V+` 接 12 V。
所以 12 V 一断，比较器整个失效、开集输出松开，**两条故障线仍然读到高电平**——
看起来「无故障」，实际什么都没在保护。

判断故障线的读数是否有意义，前提是先确认母线在 10.5 V 以上。`board_check.sh` 已内置这条。

### 1.2 烧录真的成功了

用 `flash_elf`（内部校验 `Verified OK`，失败即 `exit 1`）。

**绝不要把 openocd 的输出重定向到 `/dev/null`。** 本轮曾因此连续三次烧录静默失败，
之后抓到的「引脚不动」波形其实来自一颗还跑着旧固件的芯片。

### 1.3 CPU 真的在跑

`program ... reset` 会在 `Reset_Handler` 留断点，CPU 停在那里根本到不了 `main`，
外设全不动、电流 6 mA——极易误读成「固件没输出」。

`flash_elf` 已包含 `rbp all` + `resume`。若手写 openocd 命令，必须自己加。

确认办法用 `cpu_alive`（`bench_common.sh`）：它读两次 HAL 的 `uwTick`（每 1 ms 自增），
不相等即证明 `main()` 在跑。比 halt 后看 PC 更轻，也不扰动被测系统。

### 1.3.1 不要硬编码 RAM 地址

**布局会随代码改动漂移。** 文档曾记录 openloop 快照在 `0x200000fc`，而链接器早已把它放到
`0x200000b4`；`pole_pairs.sh` 里硬编码的 `0x20000120` 更是两者都不是，读到的是垃圾。

用 `sym_addr <符号名>`（`bench_common.sh`，底层是 `arm-none-eabi-nm`）从 ELF 解析：

```bash
SNAP=$(sym_addr s_hall6_snap)   # hall6；hall_changes 在 +12
SNAP=$(sym_addr s_ol_snap)      # openloop
```

两个快照原先都叫 `s_snap`，同名 static 让 `nm` 的结果无法区分——**这就是当初记错地址的根源**，
现已改名。字段顺序见对应 `.h`，注意**小端字节序**。

### 1.4 参数真的生效了

**不要假设传进去的 cmake 参数就是芯片上跑的值。** 两种翻车方式都发生过：

1. **cmake cache 残留**：所有 `MOTOR_*` 都是 cache 变量，复用旧 build 目录会沿用上次的值。
   切换参数组时先 `rm -rf build/Release`，或显式传全部相关选项。
   本轮曾出现「传了 `RUN_DUTY=20`，芯片上跑的是 12」。
2. **函数内部静默限幅**（见下表）。

**做法：从芯片读回快照确认，而不是看自己传了什么。** 例如 hall6 的 `duty_pct` / `phase` /
`direction` 都在 `0x20000040` 的前 8 字节里。

#### 静默限幅一览

| 函数 | 限幅 |
|---|---|
| `MotorOpenloop_SetStepMs` | 非零值限到 **5..500 ms**；**0 = 静态保持不换相** |
| `MotorOpenloop_SetDutyPct` | ≤ **25** (`MOTOR_OPENLOOP_MAX_DUTY`) |
| `MotorOpenloop_SetPulseCounts` | ≤ **360** (`OL_PULSE_COUNTS_MAX`) |
| `MotorHall6_SetDutyPct` / `SetKickDutyPct` | ≤ **25** (`MOTOR_HALL6_MAX_RUN_DUTY`) |
| `MotorHall6_SetPhaseOffset` / `MotorOpenloop_SetHallPhase` / `SetUvPerm` | 取模 6 |

`SetStepMs` 这一条曾把 `60000` 压成 500 ms，导致一整批「固定单步不换相」的实验
其实每 500 ms 就换一次相。**受影响的结论全部作废**（包括当时那张「六步电流完全对称」的表——
六个数一样是因为每档 4 秒里换了 8 次相，测的是全步平均值）。

### 1.5 被测对象真的在回路里

**先确认电机接上了、相线落在正确端子上。** 本轮有很长一段时间电机根本没接进电气网络，
而所有分析都在讨论「桥臂为什么短路」。

断电用万用表量：三相相间应是**三个相等的几十~几百 mΩ**（本电机 1.3 Ω），
短接其中两相后手转轴应明显变重（发电制动）。这两条同时成立才说明绕组和磁钢都正常。

### 1.6 工作点在有效区（电源没进限流）

母线电流应随 duty 呈**平方**关系：`I_bus = D_eff² · V / R`。

如果电流**撞在某个值上不随 duty 变化**，说明电源进了 CC、母线已塌陷，
**此时所有软件层面的对比实验都无意义**。本轮曾在这种状态下扫了 36 种
（线序 × phase × 方向 × 开环/闭环）组合，全部无效。

本实验装置：母线 12 V，绕组相间 1.3 Ω，hall6 稳态约 60 mA。

电源是 **GW Instek GPC-3030DN**（0~30 V / 0~3 A × 2 + 固定 5 V，线性）。三件事要知道：

1. **面板电流表分辨率是 10 mA**（额定 3 A → 19.99 A 满量程），所以空载 4 mA、
   静态步 20 mA 时读 0.00 是正常的，**不是表坏了**。真正的电流读数靠串在母线上的 UT61E。
   另外 D/DN 型每通道只有一个显示器，靠 **A/V 开关**决定显示电压还是电流。
2. **限流值要按手册 §5-2 标定**：断开负载，直接在电源输出端子上短路（**不要经过 UT61E**，
   mA 档会烧保险丝），此时 C.C. 灯亮、面板显示的就是限流值，转 CURRENT 旋钮到目标值。
3. **判断有没有进 CC 不要靠读数，靠两个东西**：面板的 **C.C. 指示灯**
   （手册：CC indicator lights when this unit in constant current operation），
   以及 **PA4 的母线电压**——空载 11.98 V，进 CC 会明显塌陷。`board_check.sh` 已把
   母线电压做成判据，`hall6_regress.sh` 在带载时也检查它。

### 1.7.1 读缓冲期间缓冲不能还在被写

trace 缓冲 256 拍只覆盖 **12.8 ms**，而 openocd 读 512 个字要约 **1 s**。
在 wrap 模式下边跑边读，缓冲会被覆写近 **80 遍**，拿到的是几十个不相干片段的拼接——
**看起来是一段规整波形，时间轴却完全是假的**。本轮第一次抓取就踩了：
12.8 ms 里只出现 4 个 hall 码、扇区时长离谱、推出的转速是真实值的两倍。

两种正确用法，共同点是**读之前让缓冲静止**：

| 模式 | 用法 |
|---|---|
| one-shot | armed → 填满 256 拍自动停 → 从容读出。适合抓瞬态 |
| wrap | 需要时写 `mode=0` 冻结 → 读出冻结前的最后 256 拍。**冻结只停记录，电机照常转** |

`trace_dump.py` 会在读缓冲前自动冻结，并打印提示。

**判据（务必保留）**：固件在看到新 hall 码的那一拍把 `ticks_since_edge` 归零，
所以导出后**每个 hall 边沿样本的 `ticks_since_edge` 必须小于抽取比**。
只要有一个不满足，这份采样就不是连续拍，时间轴和由它算出的转速一律作废。
脚本已把这条做成自动检查（`TORN CAPTURE`）。

### 1.8 时间窗口里不要夹别的操作

要测一个计数器的速率（`loop_count`、`hall_changes`），两次读之间**只能有等待**。

本轮实测：控制环真值 20 kHz，却量出 25673 Hz。原因是两次读快照之间除了 `sleep 6`
还夹着一次 benchgate 读表和一次 openocd 进程启动，实际间隔约 7.7 s 而除数用的是 6，
`20000 × 7.7/6 = 25673` 正好对上。同一个错误把转速也抬高了 28%。

两条对策，都要做：

1. **把两次读放进同一个 openocd 会话**，用它自己的 `sleep` 隔开
   （`hall6_regress.sh` 的 `snap_pair`），进程启动开销就落在窗口之外。
2. **优先找确定性判据代替计时**。控制环频率由寄存器唯一决定：
   `f = 48 MHz / (2·(ARR+1)) · 2 / (RCR+1)`，读 `ARR`/`RCR` 就能算出来，
   完全不依赖主机计时。主机计数只用来确认 ISR 没漏拍（两者应一致到 2% 内）。

### 1.7 寄存器读写工具的语义

OpenOCD `mmw <addr> <setbits> <clearbits>` 实测是**先置位再清位，clearbits 覆盖 setbits**。
掩码重叠时结果恒为 0。本轮的 AF 扫描因此八次全写成 AF0，得出「PA7 上没有 TIM1_CH1N」的
错误结论——实际它工作正常。

**改一个位域要用两条命令**：先 `mmw addr 0 <field_mask>` 清零，再 `mmw addr <value> 0` 置值，
并且**读回确认**。

| 事故 | 表象 | 被误判为 | 自检项 |

| `Reset_Handler` 断点未清 | 空载电流、外设全不动 | 固件无输出 | 1.3 |
| openocd 输出被吞 | 抓到的波形全平 | 引脚不动 / 硬件坏 | 1.2 |
| nanoDAP 掉线 | 0.000 A、三路全平 | 板子烧了 | 1.1 |
| 12 V 未上 | `nFAULT`/`nOTEMP` 读高 | 保护正常工作 | 1.1.1 |
| 硬编码 RAM 地址过期 | 快照字段是垃圾值 | 固件没在更新状态 | 1.3.1 |
| `SetStepMs` 静默限幅 | 六步电流全相同 | 三相对称、功率级正常 | 1.4 |
| cmake cache 残留 | 行为与参数不符 | 代码逻辑有问题 | 1.4 |
| 电机未接入 | 电流线性 ∝ 导通时间、无电感特征 | 桥臂内部短路 | 1.5 |
| 电源进 CC | 36 种组合电流全相同 | 换相 / 线序 / Hall 全错 | 1.6 |
| 面板电流表读 0 | 限流读数「损坏」 | 仪器故障（实为 10 mA 分辨率） | 1.6 |

| 边读边写 trace 缓冲 | 规整但错误的波形，转速差 2 倍 | Hall 少了两个码 / 传感器坏 | 1.7.1 |
| 计时窗口里夹了其他操作 | 控制环「跑在 25.7 kHz」 | `RCR` 被改坏 | 1.8 |
| 用带载时间测量标定几何量 | 六个 Hall 扇区「偏差 9°」 | Hall 安装角偏差（含力矩脉动） | 3.6 |
| 拿示波器当幅度基准 | 「建立时间 24 µs」 | INA240 太慢 | 3.7 |

| 诊断信号耦合进模拟线 | 采样窗口附近 185 mV 尖峰 | 功率级开关噪声 | 3.9 |

共性：**装置坏了，但结论记在了被测对象头上。**
所以遇到负面结果时，第一反应应该是「先证明装置是活的」，而不是「继续换参数试」。

## 3. 判据设计原则

### 3.1 用函数形状，不用单点数值

这轮两次真正的突破都来自形状，不是数值：

- 电流 **∝ 导通时间**（线性）→ 电容充放电；电流 **∝ duty²**（平方）→ 真实绕组电流。
  拆掉 VOUT 电容后斜率从 0.052 A/计数 塌到平的 10 mA，同时曲线从线性变平方，
  两个特征同时翻转才足以定性。
- 死区在 **0.5 → 6.67 µs（13 倍）范围内电流完全不变** → 排除了穿通假设。

而「1.12 A」这个数值本身误导了很久——它是电源限流值，压根不取决于固件。
**扫参数时至少取 3 个点看趋势，不要只比较单点数值。**

### 3.2 数值吻合 ≠ 机理相同

我们把 TARS 的 300 mA 复现到 3% 以内（0.319 A vs 300 mA），**电机却完全静止**。
同一个电流值可以由完全不同的机理产生。

**任何「和参考实现对上了」的结论，必须有一个独立的第二判据。**
这里的第二判据是 `hall_changes` 是否增长——它当时是 0。

### 3.3 移植要对齐物理量，不是配置数字

照抄 TARS 的 `duty 7%` 是错的：死区要从 HS 脉冲里减掉，
TARS 3 µs 死区下 7% 只剩 0.5 µs 有效导通，而本板 1.5 µs 死区下同样 7% 是 4 倍驱动量。
另外 `DTG` 是**非线性编码**，`DTG=144` 实际 3.33 µs 而非 3 µs。

**跨 MCU / 跨平台移植时，对齐的必须是有效导通时间、实际频率、实际电流这类物理量。**

### 3.4 一次只动一个变量，且改完要能读回

改完必须能从芯片读回确认生效（1.4），否则「改了没效果」和「没改上」无法区分。

### 3.7 示波器不一定比被测系统精确

本项目的直觉反了：**示波器在这条链路上的分辨率比板载 ADC 差 20 倍。**

DS1104Z 垂直是 8 bit。设 500 mV/div 时满屏 4 V，量化步长 `4/256 = 15.6 mV`，
经 INA240（增益 50）和 10 mΩ 分流折算是 **31 mA**。而板载 ADC 是 12 bit / 3.3 V，
**1.6 mA/LSB**。

实际代价：我用示波器量 INA240 建立时间，算出「尾部噪声标准差 11.7 mV」并据此设判据带，
得到 24 µs 的荒谬结果——那 11.7 mV 几乎全是示波器自己的量化误差。
把 CH3 改到 50 mV/div（量化 1.56 mV）才量出真实的约 2 µs。

**结论**：示波器在这里的用途是**定时**（4 ns 分辨率，无可替代），不是幅度。
要测幅度就把垂直档细化到信号本身的动态范围，或者干脆信 ADC。

### 3.8 单阈值判沿会被振铃骗，稀疏打印会漏掉窄脉冲

同一份波形，两个分析错误：

1. **单阈值过零判沿**：1.2 ms 里数出 33 个上升沿、34 个下降沿，而实际只有 24 个 PWM 周期。
   振铃穿越阈值被当成了额外的沿，于是「高边导通 15.53 µs / `D_eff` 31%」——比真值大一倍多。
   改成 **25%/75% 施密特判据**后立刻得到 24/24 和 7.02 µs（`D_eff` 14.05%，与模型差 0.9%）。
2. **稀疏打印**：以 0.5 µs 间隔打印 4 ns 采样的波形，会漏掉宽度约 100 ns 的尖峰。
   一度因此认为「波形是平的、24 µs 处的异常不存在」，实际那里有诊断时标耦合进来的
   90~185 mV 尖峰（折算 180~370 mA）。

对策：判沿一律带滞环；**找异常要在全分辨率下取极值，不要靠肉眼扫抽样表格**。

### 3.9 诊断信号自己会污染被测信号

阶段 C 的采样时标是 PA15 上一个 1.5 µs 宽的 3.3 V 脉冲。实测它的两个沿在三路 ISENSE 上
分别耦合出 **+155 / −185 / −93 mV** 的尖峰——而满量程信号只有 ±30 mV（分流上）。

这次没造成伤害，纯属运气：DMA 中断延迟让时标比真实采样窗口晚约 1.6 µs，
四次转换都在尖峰之前完成，ADC 实测噪声仍是 3 mA。**若延迟再短一点就会打进采样窗口。**

所以 `MOTOR_ADC_STROBE` 默认关闭，只在示波器会话里开。
更一般的教训：往一个 ±30 mV 的模拟系统里加任何逻辑电平的诊断信号，都要先假设它会污染测量。

### 3.6 别用受扰的量去标定几何量

想从 Hall 边沿的**时间间隔**反推六个锚点的**角度**，前提是转速恒定。而带载运行时
6-step 换相本身产生周期-6 的力矩脉动，它对时间间隔的影响与要标定的几何偏差**同量级**，
且同样锁定在 Hall 码上——单次测量无法分离。

实测证据（duty 20%，24.8 电周期/s）：六个扇区角宽 `[59.5, 51.5, 64.2, 66.4, 55.3, 67.8]` 度，
转与转之间重复到 1.5%，看着像可靠的几何标定结果。但

- 换到 8.4 电周期/s，偏差**变大**（spread 21.9° vs 16.5°）——惯量在高速下平滑掉一部分，
  说明其中含转速波动成分；
- **反转后同一个码的角宽变化最多 7°**，与几何偏差本身同量级——霍尔磁滞折算的角度偏移
  逐个传感器不同，加上反转时力矩脉动相对 Hall 码的相位也变了。

**正确做法是换一个不受该扰动影响的仪器。** 这里是 FOC 的 `id`：角度对齐错了 `id` 就不为零，
而 `id` 响应的是角度误差本身，与转速波动无关。所以锚点标定要放到有电流采样之后
（roadmap 阶段 E 第一步的「只观测不闭环」），而不是靠时间间隔。

### 3.5 参考实现不是真理

TARS 的 `hall6_lookup(hall, ccw)` 留了换向参数但调用处硬传 0，移植时被当作冗余删掉——
结果反向能力从来没接上。TARS 那边「300 mA 能转」的现象至今无法自洽解释（该板已烧毁，无法复测）。

**参考实现只用来提供思路，不能用来证明正确性。**

## 4. 最小自检序列

任何一轮测量的固定开头与收尾：

```bash
source src/firmware/stm32f030/scripts/bench_common.sh

require_dap                 # 1.1 探头在线
# ... cmake 配置（切参数组先 rm -rf "$BUILD"）+ 构建 ...
flash_elf                   # 1.2 校验 Verified OK；内含 rbp all + resume (1.3)
# 从芯片读回参数确认生效 (1.4)
# 读两次 loop_count 确认在跑 (1.3)
# 确认电流随 duty 呈平方、没撞限流 (1.6)

# ... 测量 ...

motor_off                   # 停机
# 刷回 AUTO_START=OFF 安全固件，确认空载回到约 6 mA
```

三个扫描脚本（`duty_sweep.sh` / `ccr_sweep.sh` / `step_table.sh`）已内置
探头预检、烧录校验和安全收尾，能用它们就不要手写 openocd 命令。
