# 测量有效性：如何不被自己的实验骗

面向**接手执行的 agent**。这份文档不讲电机原理，只讲一件事：
**在相信任何一个读数之前，先证明测量链是活的。**

背景：hall6 移植期间，两个 agent 累计至少 7 次因为「测量装置本身是坏的」而得出自信的错误结论，
把负面结果归因给了被测对象。真正的三个根因（低边 `CCR=0`、`RCR=0`、VOUT 滤波电容）
每一个都被这类无效实验掩盖过。技术性的坑见
[`src/firmware/stm32f030/README.md`](../src/firmware/stm32f030/README.md#已知陷阱)，
这里只讲方法。

---

## 1. 通电前自检清单

**每次测量前按顺序过一遍。任何一项不通过，读数一律作废。**

### 1.1 探头在线

```bash
source src/firmware/stm32f030/scripts/bench_common.sh
require_dap
```

**MCU 由 nanoDAP 供电。** 探头掉线的表象是「母线 0.000 A、所有引脚全平」，
和「板子烧了」完全一样。注意区分：正常待机是约 **6 mA**，**0.000 A 说明 MCU 没上电**。

### 1.2 烧录真的成功了

用 `flash_elf`（内部校验 `Verified OK`，失败即 `exit 1`）。

**绝不要把 openocd 的输出重定向到 `/dev/null`。** 本轮曾因此连续三次烧录静默失败，
之后抓到的「引脚不动」波形其实来自一颗还跑着旧固件的芯片。

### 1.3 CPU 真的在跑

`program ... reset` 会在 `Reset_Handler` 留断点，CPU 停在那里根本到不了 `main`，
外设全不动、电流 6 mA——极易误读成「固件没输出」。

`flash_elf` 已包含 `rbp all` + `resume`。若手写 openocd 命令，必须自己加。
确认办法：隔几秒读两次 `loop_count`，应持续增长。

| 变量 | 地址 |
|---|---|
| hall6 `s_snap` | `0x20000040`（`loop_count` 在 +8） |
| openloop `s_snap` | `0x200000fc`（`loop_count` 在 +0x14 = `0x20000110`） |

字段顺序见对应 `.h`，注意**小端字节序**。

### 1.4 参数真的生效了

**不要假设传进去的 cmake 参数就是芯片上跑的值。** 两种翻车方式都发生过：

1. **cmake cache 残留**：所有 `MOTOR_*` 都是 cache 变量，复用旧 build 目录会沿用上次的值。
   切换参数组时先 `rm -rf build/Release`，或显式传全部相关选项。
   本轮曾出现「传了 `RUN_DUTY=20`，芯片上跑的是 12」。
2. **函数内部静默限幅**（见下表）。

**做法：从芯片读回快照确认，而不是看自己传了什么。** 例如 hall6 的 `duty_pct` / `phase` /
`direction` 都在 `0x20000040` 的前 8 字节里。

#### 静默限幅一览

| 函数 | 限幅 |
|---|---|
| `MotorOpenloop_SetStepMs` | 非零值限到 **5..500 ms**；**0 = 静态保持不换相** |
| `MotorOpenloop_SetDutyPct` | ≤ **25** (`MOTOR_OPENLOOP_MAX_DUTY`) |
| `MotorOpenloop_SetPulseCounts` | ≤ **360** (`OL_PULSE_COUNTS_MAX`) |
| `MotorHall6_SetDutyPct` / `SetKickDutyPct` | ≤ **25** (`MOTOR_HALL6_MAX_RUN_DUTY`) |
| `MotorHall6_SetPhaseOffset` / `MotorOpenloop_SetHallPhase` / `SetUvPerm` | 取模 6 |

`SetStepMs` 这一条曾把 `60000` 压成 500 ms，导致一整批「固定单步不换相」的实验
其实每 500 ms 就换一次相。**受影响的结论全部作废**（包括当时那张「六步电流完全对称」的表——
六个数一样是因为每档 4 秒里换了 8 次相，测的是全步平均值）。

### 1.5 被测对象真的在回路里

**先确认电机接上了、相线落在正确端子上。** 本轮有很长一段时间电机根本没接进电气网络，
而所有分析都在讨论「桥臂为什么短路」。

断电用万用表量：三相相间应是**三个相等的几十~几百 mΩ**（本电机 1.3 Ω），
短接其中两相后手转轴应明显变重（发电制动）。这两条同时成立才说明绕组和磁钢都正常。

### 1.6 工作点在有效区（电源没进限流）

母线电流应随 duty 呈**平方**关系：`I_bus = D_eff² · V / R`。

如果电流**撞在某个值上不随 duty 变化**，说明电源进了 CC、母线已塌陷，
**此时所有软件层面的对比实验都无意义**。本轮曾在这种状态下扫了 36 种
（线序 × phase × 方向 × 开环/闭环）组合，全部无效。

本台架：母线 12 V，电源限流约 1.6 A，绕组相间 1.3 Ω。稳态约 60 mA 有充足余量。

### 1.7 寄存器读写工具的语义

OpenOCD `mmw <addr> <setbits> <clearbits>` 实测是**先置位再清位，clearbits 覆盖 setbits**。
掩码重叠时结果恒为 0。本轮的 AF 扫描因此八次全写成 AF0，得出「PA7 上没有 TIM1_CH1N」的
错误结论——实际它工作正常。

**改一个位域要用两条命令**：先 `mmw addr 0 <field_mask>` 清零，再 `mmw addr <value> 0` 置值，
并且**读回确认**。

## 2. 无效实验模式速查

| 事故 | 表象 | 被误判为 | 自检项 |
|---|---|---|---|
| `Reset_Handler` 断点未清 | 6 mA | 固件无输出 | 1.3 |
| openocd 输出被吞 | 抓到的波形全平 | 引脚不动 / 硬件坏 | 1.2 |
| nanoDAP 掉线 | 0.000 A、三路全平 | 板子烧了 | 1.1 |
| `SetStepMs` 静默限幅 | 六步电流全相同 | 三相对称、功率级正常 | 1.4 |
| cmake cache 残留 | 行为与参数不符 | 代码逻辑有问题 | 1.4 |
| 电机未接入 | 电流线性 ∝ 导通时间、无电感特征 | 桥臂内部短路 | 1.5 |
| 电源进 CC | 36 种组合电流全相同 | 换相 / 线序 / Hall 全错 | 1.6 |
| `mmw` 掩码重叠 | 八种 AF 全无输出 | 引脚无此复用功能 | 1.7 |

共性：**装置坏了，但结论记在了被测对象头上。**
所以遇到负面结果时，第一反应应该是「先证明装置是活的」，而不是「继续换参数试」。

## 3. 判据设计原则

### 3.1 用函数形状，不用单点数值

这轮两次真正的突破都来自形状，不是数值：

- 电流 **∝ 导通时间**（线性）→ 电容充放电；电流 **∝ duty²**（平方）→ 真实绕组电流。
  拆掉 VOUT 电容后斜率从 0.052 A/计数 塌到平的 10 mA，同时曲线从线性变平方，
  两个特征同时翻转才足以定性。
- 死区在 **0.5 → 6.67 µs（13 倍）范围内电流完全不变** → 排除了穿通假设。

而「1.12 A」这个数值本身误导了很久——它是电源限流值，压根不取决于固件。
**扫参数时至少取 3 个点看趋势，不要只比较单点数值。**

### 3.2 数值吻合 ≠ 机理相同

我们把 TARS 的 300 mA 复现到 3% 以内（0.319 A vs 300 mA），**电机却完全静止**。
同一个电流值可以由完全不同的机理产生。

**任何「和参考实现对上了」的结论，必须有一个独立的第二判据。**
这里的第二判据是 `hall_changes` 是否增长——它当时是 0。

### 3.3 移植要对齐物理量，不是配置数字

照抄 TARS 的 `duty 7%` 是错的：死区要从 HS 脉冲里减掉，
TARS 3 µs 死区下 7% 只剩 0.5 µs 有效导通，而本板 1.5 µs 死区下同样 7% 是 4 倍驱动量。
另外 `DTG` 是**非线性编码**，`DTG=144` 实际 3.33 µs 而非 3 µs。

**跨 MCU / 跨平台移植时，对齐的必须是有效导通时间、实际频率、实际电流这类物理量。**

### 3.4 一次只动一个变量，且改完要能读回

改完必须能从芯片读回确认生效（1.4），否则「改了没效果」和「没改上」无法区分。

### 3.5 参考实现不是真理

TARS 的 `hall6_lookup(hall, ccw)` 留了换向参数但调用处硬传 0，移植时被当作冗余删掉——
结果反向能力从来没接上。TARS 那边「300 mA 能转」的现象至今无法自洽解释（该板已烧毁，无法复测）。

**参考实现只用来提供思路，不能用来证明正确性。**

## 4. 最小自检序列

任何一轮测量的固定开头与收尾：

```bash
source src/firmware/stm32f030/scripts/bench_common.sh

require_dap                 # 1.1 探头在线
# ... cmake 配置（切参数组先 rm -rf "$BUILD"）+ 构建 ...
flash_elf                   # 1.2 校验 Verified OK；内含 rbp all + resume (1.3)
# 从芯片读回参数确认生效 (1.4)
# 读两次 loop_count 确认在跑 (1.3)
# 确认电流随 duty 呈平方、没撞限流 (1.6)

# ... 测量 ...

motor_off                   # 停机
# 刷回 AUTO_START=OFF 安全固件，确认空载回到约 6 mA
```

三个扫描脚本（`duty_sweep.sh` / `ccr_sweep.sh` / `step_table.sh`）已内置
探头预检、烧录校验和安全收尾，能用它们就不要手写 openocd 命令。
