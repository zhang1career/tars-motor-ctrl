# motor-ctrl 路线图：从 Hall 6-step 到 FOC / 弱磁 / 动态性能

面向**接手执行的 agent**。每一阶段都给出入口条件、做法、验收判据和失败回退。
**不要跳阶段**：后一阶段的调试严重依赖前一阶段建立的观测能力和标定结果。

## 0. 开工前必读

### 0.1 硬件事实（不要凭猜测改）

| 项 | 值 | 影响 |
|---|---|---|
| MCU | STM32F030K6，Cortex-**M0** @ 48 MHz | **无 FPU、无硬件除法、无 DWT 周期计数器** |
| Flash / RAM | 32 KB / **4 KB** | 当前已用约 11.4 KB / 1.6 KB；RAM 余量约 2.4 KB |
| 功率级 | 3 × 半桥板（UCC27211 + AOD4184） | 高边自举，**必须靠本臂低边把 SW 拉低才能充电** |
| 电流采样 | 主板 v0.1 的 3 × **INA240A2**（增益 50）差分前端，从半桥 `J2` 取 Kelvin 对 → PA1/PA2/PA3 | **实测 1.617 mA/LSB**（VDDA 3.311 V），比裸分流 80.6 mA/LSB 好 50 倍。零点恒为 **2048 counts**（参考与 ADC 同源、比例跟踪），实测三路都在 ±3 LSB 内。符号：`i_phase = −(code − 2048) × 1.617 mA` |
| V_BOOST | 板载 3-BJT 电荷泵，**当前不启泵**（PA11 输出低），`V_BOOST` **实测 11.74 V** | 空载下 `D2`/`D3` 只流 µA 级、`Vf` 约 0.15 V，所以比「10.6 V」的手算值高。经半桥 `D1` 给 `HB` 约 11.1 V，而片内自举给约 11.3 V，两条路等价且都在 8~17 V 推荐窗口内 |
| 电机 | BLDC，相间电阻 **1.3 Ω**，**4 极对**，Hall 在 PB3/PB4/PB5 | 相间 1.3 Ω 是所有电流估算的基准 |
| 母线 | **12 V**（PA4 实测空载 11.98 V），电源 **GW Instek GPC-3030DN** | 限流旋钮无法精确设定，面板电流表分辨率 10 mA。**进 CC 靠 C.C. 指示灯与 PA4 电压塌陷判定**，不靠读数，见 0.5 与 `measurement-validity.md` 1.6 |
| PWM | TIM1 20 kHz 中心对齐，DTG=72（1.5 µs 死区） | 控制环 20 kHz = **每拍 2400 周期** |

**半桥板 VOUT 对地的滤波电容已拆除，必须保持拆除状态。** 那块板原设计是 buck 输出级，
VOUT 上的电容会被高边充、低边放，形成约 96 mΩ 的寄生通路吃掉约 1.5 A，电机拿不到功率。
如果发现母线电流异常大且**与 duty 成线性**（而非平方），第一件事就是检查这个电容是否被装回。

### 0.2 安全协议与测量有效性（每次通电测试都必须遵守）

**先读 [`measurement-validity.md`](measurement-validity.md)。** 那份文档列出了通电前自检清单、
函数内部的静默限幅、以及本项目已发生过的 8 种「装置坏了却归因给被测对象」的无效实验模式。
不过这一关就不要开始测——本轮真正的三个根因都曾被这类无效实验掩盖过。


1. 测试前确认探头在线：`require_dap`（见 `src/firmware/stm32f030/scripts/bench_common.sh`）。
   **MCU 由 nanoDAP 供电**，探头掉线时表现为「母线 0.000 A 且完全无 PWM」，极易误判成硬件坏。
2. 每次测试结束**必须**停机并刷回安全固件（`MOTOR_AUTO_START=OFF`），然后确认空载电流
   回到约 **6 mA**。三个扫描脚本已内置这个收尾。
3. 不要在无人观察时让电机长时间带电。历史上曾把约 1 A 长时间挂在板上，导致 3 号板过热。
4. **不要为了让实验通过而调高电源限流。** 限流撞顶说明工作点选错了或有寄生通路，
   先找原因。判据：母线电流应随 duty 呈**平方**关系（`I_bus = D_eff² · V / R`）。
5. 烧录后 OpenOCD 的 `program ... reset` 会在 `Reset_Handler` 留断点，
   **测量前必须 `rbp all` + `resume`**，否则 CPU 根本没跑到 `main`。`flash_elf` 已包含。

### 0.3 待决项（硬件侧，会决定算法能做到什么程度）

这几项**不是算法能补偿的**，越早定越好。定了就更新本表并记录决策理由。

| # | 待决项 | 现状 | 影响 |
|---|---|---|---|
| 1 | **电流采样前端增益** | **已解决**：主板 v0.1 已打样装配并实测，1.617 mA/LSB，三路零点在 2048 ±3 LSB。见 [`mainboard-spec.md`](mainboard-spec.md) §1 与本文 1.2.1 | 不再是瓶颈；3.4 里「电流环反馈只够做限流」的结论随之作废 |
| 2 | **PA11 归属** | **已解决**：外部电荷泵保留，PA11/TIM1_CH4 留给它。ADC 改用 `TIM1_TRGO` ← update 事件 | CC4 作为 ADC 触发是**内部事件**、本不占引脚，但 CCR4 会被电荷泵占用，故走 TRGO。见 `mainboard-spec.md` §3.1 |
| 3 | **母线储能 / 电源** | 实验电源限流约 1.6 A | 动态测试与弱磁的硬阻塞，见 0.5 |

### 0.4 已知陷阱（改 PWM / 换相代码前必读）

完整列表见 [`src/firmware/stm32f030/README.md`](../src/firmware/stm32f030/README.md#已知陷阱)。
最容易重复踩的四条在此重述：

1. **低边常通不能用 `CCR=0`。** `CCxE=0, CCxNE=1` 时 OCxN 引脚**直接跟随 OCxREF**（不反相、
   不插死区），`CCR=0` 会让低边恒关、回流臂断开、电机零力矩。必须 `CCR = ARR + 1`。
2. **中心对齐必须 `RepetitionCounter = 1`。** 上溢和下溢各产生一次 update 事件，
   `RCR=0` 时控制环跑在 `2 × MOTOR_PWM_HZ`，所有基于 `MOTOR_CTRL_ISR_HZ` 的时间常数都差一倍。
3. **DTG 是非线性编码，且死区要从 HS 脉冲里减掉。** 有效导通 = `2×CCR − DT`。
   跨 MCU 移植要对齐**有效导通时间**，不是 duty 百分比数字。
4. **换向必须换驱动表（交换 PWM 相与 LOW 相），不能只移相。**
   `s_seq_ccw` 是 `s_seq_cw` 的反序，等价于偏移 `−p`，而 `−p ≡ p (mod 6)` 恰好落在
   phase 0 和 3——偏偏这两个是唯一高效的偏移。

### 0.5 电源限流对动态测试的影响

限流约 1.6 A 时，稳态 60 mA 有充足余量，但**加速、堵转、负载突变的瞬态峰值会撞顶**，
母线电压塌陷，测出来的动态响应是电源的、不是电机的。进入阶段 E 之前必须先解决：
用容量更大的电源，或在母线上加足够的储能电容（注意：**加在 VIN，绝不能加回 VOUT**）。
无论选哪条，都要在报告里记录电源型号与限流设定值。

## 1. 当前基线（已验证，作为回归基准）

控制方式：**hall6 闭环 6-step**（`MotorApp_Start()` → `MotorHall6_Enable(1)`），
内部先开环 kick（≤40 步 / 30 ms 每步，拿到 2 次 Hall 同步即提前退出），再转 Hall 边沿换相。

固件默认值（`src/firmware/stm32f030/App/motor_app.c`）：

```
phase 3, kick duty 20%, run duty 20%, direction 0（顺时针；1 为逆时针）
TIM1 20 kHz 中心对齐, DTG=72, 控制环 20 kHz
```

## 2. 阶段 A：建立观测能力（**最高优先，先做这个**）

### 为什么先做

FOC 的电流环是每拍级别的行为。现在唯一的读数手段是 `halt` + `mdw`，单次约 1.5 s，
而且 halt 会**停掉换相**、扰乱被测系统。用这种手段调 FOC 等于盲调。
先花小代价把观测建起来，后面每一阶段都受益。

### A1. 片上 RAM 环形缓冲 + 批量 SWD 导出

- 在 `src/platforms/stm32f030/` 新增 `motor_trace.c/.h`。
- 固定大小 `int16_t` 缓冲，编译期可配通道数与深度。**RAM 只剩约 2.4 KB**，
  建议 4 通道 × 256 点（2 KB）起步，`MOTOR_TRACE_DEPTH` 可配。
- ISR 里调用 `MotorTrace_Push(ch0, ch1, ch2, ch3)`，**只做数组写入和索引自增，禁止任何除法或浮点**。
- 支持一次性（写满即停）和连续覆盖两种模式；一次性模式便于抓单次瞬态。
- 主机侧用 `openocd -c 'mdw <addr> <n>'` 批量导出，Python 解析成 npz。
  参考 `scripts/bench_common.sh` 里已有的 openocd 调用方式。

**验收**：能在电机运行中抓到连续 256 拍的 4 通道数据并画出波形，且抓取过程不 halt CPU
（写缓冲时不停机，写满后再 halt 导出）。用已知的 24 电周期/s 换相作为自检——
把 `hall_raw` 作为其中一个通道，导出后应看到规整的 6 步循环。

### A1 完成情况（2026-08-27）

`src/platforms/stm32f030/motor_trace.{c,h}` + `scripts/trace_dump.py`，
默认 4 通道 × 256 点（2 KB），`-DMOTOR_TRACE=OFF` 可整体摘除。
**全程不 halt**——读内存走 DAP。RAM 3576 / 4096 B（其中 1.25 KB 是链接脚本预留的栈与堆）。

hall6 的四个通道是 `hall_raw, step, ticks_since_edge, kick`。
`ticks_since_edge` 不只是给阶段 D 的原料，它同时是**采样连贯性的判据**（见 1.7.1）
和一把游标卡尺：边沿前一样本的值加上「抽取比 − 边沿后第一样本的值」
就是该扇区的**精确拍数**，与抽取率无关，因此抽取到 5~14 倍去覆盖整个电周期时
时间分辨率仍是 50 µs。

验收结果：抓到完整电周期，六个 hall 码齐全，连贯性判据通过，
算出 **24.41 电周期/s** —— 与快照计数法的 24.5 独立吻合。

### A2.1 控制 ISR 各部件的实测周期数（2026-08-27）

```bash
./src/firmware/stm32f030/scripts/ctrl_bench.sh
```

走「烧录 + reset」而不是 `gdb call`（9.5），电机全程不通电。

| 部件 | median | max | 占一拍（2400） |
|---|---|---|---|
| 角度更新（无边沿） | 191 | 191 | 8.0% |
| 角度更新（有边沿，含除法） | 471 | 485 | 19.6% |
| 读三路分流并求和 | 36 | 36 | 1.5% |
| trace push | 56 | 56 | 2.3% |
| **无边沿的一拍合计** | **283** | | **11.8%** |
| **有边沿的一拍合计** | **563** | | **23.5%** |

边沿路径**不是**每拍开销：24 电周期/s 下边沿每秒 144 次，只落在 0.7% 的拍上。
把两者相加是偏悲观的算法。

**FOC 本体可用余量（按最坏的那一拍算）**：20 kHz 下 **1837** 周期，10 kHz 下 **4237**，
5 kHz 下 **9037**。

后来实测的浮点 FOC step 是 **16173** 周期，三个都放不下（见 3.3.2）。
定点版的目标就是这张表：**要在 20 kHz 跑，本体必须小于 1837 周期。**

**软浮点单次运算 169 周期**（`fmul100` 案例直接测得）。这是本平台估算浮点代价时该用的数字；
用 35 会低估 4.8 倍。

角度更新的 191 周期偏重，因为状态结构体是 `volatile`、每个字段访问都是真实的 load/store。
若阶段 E 需要这些周期，可改成内部非 volatile、末尾发布一次快照。

**计数器自校准**：100 条连续 NOP 读到 **109** 周期，超出的 9% 是 flash 等待周期。
（此前 `foc_bench.c` 用 `volatile` 循环计数器测「NOP×100」并期望 100，
实测 1619 看起来像计数器坏了——**那个期望值本身是错的**，已改为直接发 100 条 NOP。）

### A1.1 顺带得到的结论：Hall 扇区不等宽

六个扇区角宽实测 `[59.5, 51.5, 64.2, 66.4, 55.3, 67.8]` 度（duty 20%），
转与转之间重复到 1.5%，**超出阶段 D 验收线（< 5°）**。

但**不要据此标定锚点角度**：换转速偏差变大、反转后同一码角宽变化最多 7°，
说明测量被 6-step 力矩脉动和霍尔磁滞污染，污染量级与被测量相当
（推导见 `measurement-validity.md` 3.6）。折算到机械角是 ±2.25°（4 极对），
对手工贴装的霍尔板属正常公差。

→ 阶段 D 先用**均匀 60° 锚点**（最坏 ±9° 电角度误差 = 约 1.2% 力矩损失、
≤16% 电流落到 d 轴），锚点的精确标定推迟到阶段 E 第一步，用 `id` 做仪器。

### A2. 目标板执行时间测量

M0 **没有 DWT 周期计数器**，但 **TIM3 空闲**（`MotorTick_Init()` 已不再配置它）。

- 把 TIM3 配成 `PSC=0`（48 MHz）自由运行计数器，`ARR=0xFFFF`。
- 被测函数前后各读一次 `TIM3->CNT`，差值即周期数（注意 16 位回绕）。
- 交叉验证：同时翻转一个空闲 GPIO，用示波器量脉宽，两者应一致。

**验收**：能报出任意函数的周期数，误差 < 5%。先用一个已知耗时的空循环自校准。

### A3. 失败回退

如果 RAM 不够放缓冲，退化方案：只抓 2 通道 × 256 点（1 KB），或降低采样抽取率
（每 N 拍存一次）。**不要**为了塞缓冲去动 HAL 或链接脚本。

## 3. 阶段 B：FOC 时序可行性判定（**决策关口**）

### 3.1 入口条件与做法

入口条件：阶段 A2 完成（能测周期数）。

1. 把 `sim/codegen_stm32/foc_step_stm32.c` 及其依赖加入构建（先**不接入控制环**，
   只作为可独立调用的函数）。
2. 用阶段 A2 的方法测 `foc_step_stm32()` 单次调用周期数，输入用典型值（非 0、非极端值，
   因为软浮点耗时与数据相关）。多组输入各测 10 次，取中位数与最大值。

### 3.2 已知的静态分析结论（供对照，不要用它代替实测）

生成代码编译到 cortex-m0 为 1932 B，尺寸不是问题。问题是它全程 `real32_T` 浮点，
而 M0 无 FPU，符号表里全是 libgcc 调用：

```
__aeabi_fadd / fsub / fmul / fdiv / fcmpge / fcmpgt / fcmple / fcmplt
sinf × 2   cosf × 2   sqrtf × 2   浮点除法 21 处
```

粗估 8000 ~ 15000 周期。而 20 kHz 的预算是**每拍 2400 周期**，还要留给 ADC 读取、
换相输出和 trace，**FOC 本体的预算上限约 1800 周期**。

### 3.3 判据与分支

**降频不是自由选项**，先算被控对象极点：电流环的电气极点在 `f_pole = R / (2π·L)`。
电流环需要 `f_s ≥ 10 × f_pole`。

**量纲必须配对**：`R` 和 `L` 要同为每相值，或同为相间值（相间 = 2 × 每相，比值不变）。

已实测（均为相间值折半到每相）：`R = 0.65 Ω`（相间 1.3 Ω）、
`L = 437 µH`（LCR 表 1 kHz 测相间 860 / 881 / 883 µH，均值 874.7 µH）。由此：

```
τ = L/R = 673 µs        f_pole = 236 Hz        要求 f_s ≥ 10·f_pole = 2.4 kHz
```

| `f_s` | 预算（周期/拍） | `f_s / f_pole` | 可达电流环带宽 |
|---|---|---|---|
| 20 kHz（现状） | 2400 | 84.5× | 约 2000 Hz |
| 5 kHz | 9600 | 21.1× | 约 500 Hz |
| 2.4 kHz（下限） | 20000 | 10.1× | 约 240 Hz |

**结论：定点不是必需项。** 浮点静态估计 8000~15000 周期，在 5 kHz（9600）很可能直接放得下，
在 2.4 kHz（20000）必然放得下，而 5 kHz 仍有 21 倍极点余量、500 Hz 带宽完全够用。

模型自校验：`τ / PWM 周期 = 13.5` → 连续导通，与实测 `I_bus = 0.26 A @ duty 20%` 吻合。

**唯一需要回头确认的**：LCR 是 1 kHz 小信号值，工作电流下的增量电感会因饱和下降。
若每相 `L` 掉到 220 µH 以下，`f_pole` 越过 470 Hz、5 kHz 就变得勉强。
阶段 C 有了电流采样后用电流上升斜率（`di/dt = V/L`）复核一次。

| 实测周期数 | 动作 |
|---|---|
| < 1800 | 保持 20 kHz，进入阶段 C |
| 1800 ~ 9600 | **降到 5 kHz 跑浮点**（PWM 仍 20 kHz），进入阶段 C |
| 9600 ~ 20000 | 降到 2.4 ~ 5 kHz，或改定点换取更高带宽 |
| > 20000 | 只能改定点（3.7） |

### 3.3.1 实测结果与选定路线（已完成）

**实测 15~18k 周期 = 377 µs @ 48 MHz**（`MotorApp_RunFocBench`，见 `App/foc_bench.c`）。
落在「9600~20000」那一档，但要看清含义：377 µs 意味着即使 CPU 什么都不干，
控制环最高也只能到 **2.6 kHz**，而电流环要求 `f_s ≥ 2.4 kHz`——余量为零，
还没给 ADC 读取、换相输出和 trace 留任何时间。**直接用这份生成代码的路被堵死了。**

选定路线（不是回 Simulink 重新生成）：

1. **自己写一份简化的 Hall-FOC**，放 `src/platforms/stm32f030/`，
   **不修改 `sim/codegen_stm32/`**（那份留作离线参考与增益来源）。
   去掉无感观测器 + PLL + I/F 起转后只剩 Clarke → Park → 2 × PI → 逆 Park → SVPWM。
2. 每个候选实现都塞进 `ctrl_bench` 量周期数，**用实测定环频，不用估算**。

为什么不用生成器：这个规模下它省下的工作量小于它带来的不确定性，而且更要紧的是
**可调试性**——我们的观测手段是一块 `int16` 的 RAM 环形缓冲，必须知道每个数的物理含义，
而自动定点转换出来的变量名和标度都是工具选的，每改一个增益还要过一遍完整的 MATLAB 流程。

### 3.3.2 浮点方案已被实测否决（2026-08-27）

> **本节推翻了先前「第一版用浮点跑 10 kHz」的计划。** 那个计划基于「简化版约 1700~2500 周期」
> 的估算，而估算的依据是「软浮点每个运算约 35 周期」——**这个假设错了 4.8 倍。**

自写的浮点 Hall-FOC（`motor_foc.c`，去观测器、`sin`/`cos` 查表、无 libm）实测：

| 量 | 实测 |
|---|---|
| 一次完整 FOC step | **16173 周期 = 337 µs** |
| 满 CPU 可达环频 | **2.97 kHz** |
| `MotorFoc_Step` 里的软浮点调用数 | **110**（50 fmul / 19 fadd / 12 fsub / 16 比较 / 12 转换 / 1 fdiv） |
| **软浮点每次乘法** | **169 周期**（`ctrl_bench` 的 `fmul100` 直接测得） |

110 × 约 147（比较与转换比乘法便宜）= 16173，**自洽**。
而这个数与生成代码的 15000~18000 落在同一量级——原因相同，**不是生成器的问题，是软浮点的问题**。

减少运算数救不了：能去掉的（快照缩放 7 次、`inv_sqrt` 8 次、LSB→A 换算 4 次）
合计约 20 次运算 ≈ 3000 周期，剩下 90 次仍是 13000。

**所以定点不是偏好，是被实测强制的。** 规范见 3.5（禁除法、显式饱和、留保护位），
那一节的要求现在全部生效。

定点实现的完整规格（标度、常数、验收判据、明确不该做的事）已写成可移交的任务书：
[`tasks/fixed-point-foc.md`](tasks/fixed-point-foc.md)。
它的验收**不需要转电机**——周期数由 `ctrl_bench` 给，数值正确性由与浮点版的逐点对照给，
所以适合交给判断力较弱的执行者。

一处对 3.5 的偏离并已在任务书里写明理由：**信号路径不用 Q15，用整数物理单位**
（电流取 ADC LSB、电压取 µV）。Q 格式的标度因子是本项目最怕的那类隐性错误，
而物理单位把量纲写在变量名里；「积分器比信号路径宽」的要求由「µV 积分器 vs mV 信号」满足，
1 LSB 误差每拍产生 396 µV 增量，不存在积分死区。

浮点那份代码仍有用途，但换了位置：**作为观测与对照实现，跑在主循环而不是 ISR 里**。
理由是一次 16173 周期的计算无论多低频都不能放进 2400 周期的 ISR——它会挤掉后续的拍。
主循环没有这个限制，而阶段 E 第一步（只算 id/iq、不驱动）本来就不需要 20 kHz：
24 电周期/s 下扇区速率 144 Hz，主循环能跑到约 3 kHz，足够看出 id 的周期-6 模式。

**同时**：那份浮点生成代码占 12 KB flash / 0.5 KB RAM（软浮点 libm），
已从默认构建里摘出，只在 `-DMOTOR_FOC_BENCH=ON` 时链接。默认镜像回到 11.4 KB / 1.5 KB。

### 3.4 定点的能力边界（决策依据）

改定点前先明确一件事：**定点在本平台上几乎不是瓶颈，物理链路才是。**
下表把每个通道「定点能给的分辨率」和「硬件实际能给的分辨率」并排放：

| 通道 | 定点表示能给 | 物理链路能给 | 瓶颈 |
|---|---|---|---|
| 电流 | Q15 ≈ 满量程/32768 | ADC 12 bit × 3.3 V ÷ 10 mΩ = **80.6 mA/LSB** | **物理链路，差约 10 bit** |
| 角度 | Q15 → 0.011° | Hall 60° 锚点 + 转速外推 → **度级** | **物理链路** |
| sin/cos | 256 点表 + 线性插值 → 约 0.004° | — | 不是瓶颈 |
| 占空比 | Q15 | TIM1 `ARR=1199` → 0.083%/计数（约 11 bit） | **定时器** |

> **本节的电流那一行已被主板 v0.1 解决，下面的分析仅作历史记录。**
> 实测 1.617 mA/LSB（0.1 与 1.2.1），±2.9 A 满量程，零点 2048 counts。
> 「电流环反馈只够做限流」的结论**不再成立**，弱磁的前置条件（阶段 G）也随之解除。

电流那一行曾是决定性的。裸分流时工作点绕组约 1.6 A 只有 **约 20 个 LSB**；
0~3 A 全程只有 37 个 LSB（有效约 5.2 bit），再算上开关噪声，
电流环的反馈粗糙到只够做限流。

当时的结论是需要**增益约 30~70 倍并偏置到中轨**（FOC 需要有符号电流）。
主板 v0.1 用 INA240A2（增益 50、内部中轨参考）实现了这一点，
实测比裸分流好 50 倍，且零点与 VDDA 漂移无关（参考与 ADC 同源）。

### 3.5 定点实现规范（写代码时逐条对照）

1. **积分器必须比信号路径宽。** 信号 Q15，积分器用 **int32 / Q30**。
   原因：每拍增量是 `Ki · e · Ts`（`Ts = 50 µs`），若积分器也是 Q15，`e` 稍小增量就整除为 0
   → **积分死区**，稳态误差永远消不掉且正负不对称。
   可算边界：最小可分辨稳态误差 `e_min = LSB_积分器 / (Ki · Ts)`；用 Q30 时 `e_min` 远小于
   ADC 一个 LSB，因此不构成瓶颈。选定 `Ki` 后复核一次这个值。
2. **禁止除法。** M0 **没有硬件除法**，除法要么转成乘倒数、要么移位。
   任何 `/` 都要在 review 时解释清楚。
3. **每个累加点显式饱和。** M0 **没有 `SSAT`**，饱和必须用 C 写。
   溢出的后果是符号翻转 → 输出剧变 → 可能直接烧板。
4. **留保护位。** Park 有 √2、SVPWM 有 √3 的放大，中间累加用 int32，
   输入信号留 2 个保护位（有效范围压到 Q13 量级）。
5. **乘法可以放心用。** M0 有 32×32→32 乘法（STM32F0 为单周期实现），
   `Q15 × Q15 → int32` 再右移 15 位是廉价操作。用阶段 A2 的 TIM3 计数器实测确认。

### 3.6 这些边界对后续阶段的含义

| 议题 | 定点后能做到 | 被什么卡住 |
|---|---|---|
| FOC | 能转、能限流 | 精确力矩控制被 80.6 mA/LSB 卡死 |
| 弱磁 | 需要精细调节负 `id`，粗分辨率会让弱磁环来回抖动，且可能**过冲进入不可逆去磁区** | **以电流采样分辨率为前置条件**，见阶段 G |
| 动态性能 | 电流环带宽上限 ≈ `f_s/10`（20 kHz 下约 2 kHz） | 实际先被前端分辨率和采样延迟限制，而不是定点截断误差 |

### 3.7 改定点的正确做法

在 **Simulink 侧重新生成**定点代码（Q15 / Q16），`sin`/`cos` 用查表 + 线性插值，
除法尽量转成乘以倒数或移位。**不要手改生成的 C 文件**——下次重新生成就丢了，
而且手改浮点转定点极易引入标度错误。

如果无法重新生成，退化方案是自己写一份定点 FOC（M0 上典型 1000~2000 周期），
把 `sim/` 的模型仅当作算法参考和离线验证基准。

**验收**：给出实测周期数（中位数 / 最大值）、选定的控制频率、以及该频率下的余量占比。

## 4. 阶段 C：相电流采样

### 入口条件

阶段 A 完成（能抓波形），阶段 B 已确定控制频率。

### F030 的硬约束

- 只有**一个 ADC**，**没有 injected 通道**（那是 F1/F4 才有），三相电流只能**顺序采样**，
  每通道约 1 µs。
- 可用外部触发：`TIM1_TRGO`、`TIM1_CC4`、`TIM3_TRGO`（以 RM0360 为准再核一遍）。
- **PA11 = TIM1_CH4，目前在 `board_pins.h` 里标着「charge pump — unused」。**
  若用 CC4 触发 ADC，要先确认 PA11 不需要输出电荷泵驱动；若需要，改用 TIM1_TRGO。
  这个冲突**必须在写代码前决定并记录**。

### 做法

1. 采样窗口必须落在**低边导通期间**（分流电阻在低边，只有低边通时才有电流流过它）。
   当前 duty 20%、有效导通约 17%，低边导通占大头，窗口选在 PWM 周期中点附近最稳。
   用阶段 A 的 trace 记录 ADC 原始值与换相步，确认没有采在开关沿上。
2. 三相里只需采**两相**即可（第三相由 `iu + iv + iw = 0` 推出），可省时间。
   但要按当前换相步选择「哪两相此刻有电流」，否则采到浮空相。
3. 标定：不要凭电阻标称值。用已建立的关系交叉验证——
   母线电流 `I_bus = D_eff² · V / R`、绕组相间 1.3 Ω、母线 12 V。
   固定一个静态换相步（`MOTOR_STEP_MS=0`，见陷阱 4）通已知电流，
   用 DMM 读母线电流反推绕组电流，与 ADC 换算值对比。

### 验收

| 判据 | 阈值 |
|---|---|
| **有效分辨率** | 记录实测 mA/LSB 与噪声底（单位 LSB）。裸分流无增益时约 80.6 mA/LSB，见 3.4 |
| 静态步下 ADC 换算电流 vs DMM 反推值 | 误差 < 10% |
| 零电流时的偏置漂移 | 记录并在固件里做上电零点校准 |
| 采样点位置 | trace 显示落在低边导通窗口内，远离开关沿 |
| 三相和 | `iu + iv + iw ≈ 0`，残差 < 满量程 5% |

### 失败回退

如果开关噪声导致读数不可用：先延后采样点（远离沿）、延长 ADC 采样时间、
检查探头/接地。**不要**用软件滑动平均掩盖问题——那会给电流环引入延迟，后面更难查。

## 4.1 阶段 C 完成情况（2026-08-27）

`src/platforms/stm32f030/motor_adc.{c,h}`，默认 ON，`-DMOTOR_ADC=OFF` 可摘除。

### 触发链

```
TIM1 CH4 (PWM2 模式, CCR4 = ARR - MOTOR_ADC_LEAD_COUNTS) -> OC4REF
  -> TRGO -> ADC1 外部触发上升沿 -> 4 通道扫描 -> DMA1_CH1 循环
```

**为什么用 OC4REF 而不是 update 事件**：PWM2 模式下 `OC4REF` 每个 PWM 周期**只有一次上升沿**
（上行经过 `CCR4` 时），位置由 `CCR4` 精确决定且锚在计数器上。而 `CC4E` 不需要开，
所以 **PA11 仍是驱动低的 GPIO**，电荷泵不受影响——待决项 #2 担心的冲突不存在。

ADC 时钟取 **PCLK/4 = 12 MHz**（PCLK/2 是 24 MHz，超过 F030 的 14 MHz 上限），
`SMP = 7.5` 周期 → 每通道 1.67 µs，四通道（`ISENSE_U/V/W` + `VSENSE_12V`）共 6.67 µs。

### 一个必须知道的事实：控制 ISR 在计数谷底

实测 `g_motor_tick_dir = 0`（ISR 入口 `TIM1_CR1.DIR = 0`，向上计数）→
**更新事件落在计数谷底，不是峰值**。RM0091 对中心对齐 + 奇数 `RCR` 的更新事件位置本就不确定。

后果：ADC 采样在峰值（低边导通窗口中心）完成，而 ISR 在半个周期之后才读它，
**电流反馈延迟 25 µs**。采样本身是正确的（触发锚在计数器上），只是数据到达控制器时已经旧了。
阶段 E 若要消掉这 25 µs，正确做法是**让 ADC 的序列结束中断去驱动控制计算**，
而不是继续挂在 TIM1 update 上。

### 验收对照

| 判据 | 阈值 | 实测 |
|---|---|---|
| 有效分辨率 | 记录 mA/LSB 与噪声底 | **1.617 mA/LSB**，噪声 2.8~4.0 mA（约 2 LSB），**不随电流增长** |
| ADC 换算电流 vs DMM 反推 | 误差 < 10% | `D_eff > 8%` 的三点 **0.990 ± 0.020** |
| 零电流偏置 | 记录并做上电校准 | 零点恒为 2048 counts（比例跟踪），三路 ±3 LSB，**无需软件校准** |
| 采样点位置 | 落在低边导通窗口内、远离开关沿 | 序列落在 42.93 µs 窗口的 16.08~22.75 µs，**离最近沿 16.08 µs** |
| 三相和 | 残差 < 满量程 5% | rms 5.3~7.2 mA = **满量程的 0.19%** |

标定扫描（`scripts/isense_cal.sh`，静态单步）：

| duty | `D_eff` | ADC 绕组 | 母线反推 | 比值 |
|---|---|---|---|---|
| 7% | 3.92% | 342 mA | 409 mA | 0.836 |
| 12% | 8.92% | 792 mA | 819 mA | 0.967 |
| 17% | 13.92% | 1237 mA | 1243 mA | 0.995 |
| 22% | 18.92% | 1672 mA | 1660 mA | 1.007 |

低 duty 点偏低是因为母线反推含栅极驱动电流（约 1.5 mA）与死区模型误差，
而 `D_eff` 只有 3.9% 时这些被放大。**ADC 是更准的那一方**。

`I_winding / D_eff = 88.5 mA` 每 1% → 总回路 `12/8.85 = 1.356 Ω`，
而相间 1.3 Ω 加两个 MOSFET 导通电阻与两个分流约 32 mΩ 是 1.332 Ω，差 2%。

### 示波器验证（Rigol DS1104Z，`scripts/scope_capture.py`）

| 量 | 实测 |
|---|---|
| 时标周期 | **49.950 µs**（抖动 4 ns = 一个采样点）→ 20.0 kHz |
| 高边导通宽度 | **7.02 µs → `D_eff` = 14.05%**，模型 `(2·CCR−DTG)/period` 给 13.92%，**差 0.9%** |
| `ISENSE_V` 续流电平 | 1.0486 V → 1.215 A，ADC 同时读到 1.235 A，**两独立仪器差 1.6%** |
| **INA240 + RC 建立时间** | **约 2 µs**（到一个示波器量化码内），证实规格 §0.2 的假设 |

`D_eff` 模型的这次直接验证很重要——项目里所有电流估算都建立在它上面，此前只有间接证据。

### duty 上限

低边导通半窗口 = `(1236 − CCR)/48` µs，需要容纳「7 µs 前置 + 2 µs 建立」：

| duty | 半窗口 | 判定 |
|---|---|---|
| 20% | 20.8 µs | 余量充足 |
| 60% | 10.8 µs | 可以 |
| 67% | 9.0 µs | **上限** |
| 80% | 5.8 µs | 不够，须把 `MOTOR_ADC_LEAD_COUNTS` 减半 |

把前置降到 3.5 µs 可把上限推到约 80%，代价是采样点离峰值更远。
规格 §0.2 估的「约 90%」没算 7 µs 前置这一项。

## 5. 阶段 D：转子连续角度

### 入口条件

阶段 C 完成。

### 做法

Hall 只给 60° 分辨率，FOC 需要连续 θ。做法是**边沿锁相 + 转速外推**：

1. 每个 Hall 边沿给出一个确定的电角度（6 个锚点，**先按 60° 等间隔**，理由见 A1.1）。
2. 边沿之间用上一段的角速度线性外推，边沿到来时校正到锚点。
3. 低速 / 静止时外推不可靠，需要回退策略（低于某转速就切回 6-step，或用强制角度起转）。

**时基不需要额外定时器**：`ticks_since_edge`（阶段 A1 已在 hall6 的 ISR 里）就是角度的原料。
24 电周期/s 下一个扇区约 137 拍 → 分辨率 0.44° 电角度；3000 rpm 下约 17 拍 → 3.6°，仍可用。
所以 **TIM3 的输入捕获留作后备**，不在第一版引入——`motor_cycles.c` 已从 TIM3 让到 TIM16，
需要时 PB4/PB5 的 CH1/CH2 是空着的。

`sim/codegen_stm32/foc_step_stm32.c` 已留好钩子：
`g_tars_foc_hall_en`、`g_tars_foc_hall_theta`、`g_tars_foc_hall_w_est`、
`foc_step_stm32_hall_bootstrap()`。**优先复用这套接口**，不要另起一套。

### 验收

| 判据 | 阈值 |
|---|---|
| 稳态 24 电周期/s 下 θ 连续性 | 边沿处跳变 < 10° 电角度 |
| 6 个锚点的间隔 | 均匀，偏差 < 5°（不均匀说明 Hall 安装角或映射有偏） |
| 转速估计 | 与 `hall_changes` 算出的 24 电周期/s 一致，误差 < 3% |

用阶段 A 的 trace 同时记录 `hall_raw`、`theta`、`w_est` 三通道，导出后目视检查。

## 5.1 阶段 D 完成情况（2026-08-27）

`src/platforms/stm32f030/motor_angle.{c,h}`，默认 ON。单位取 **65536 计数/电周期**——
在 `uint16_t` 里自然回绕，高位可直接索引 sin/cos 表。

### 关键设计：per-sector 时长记忆

朴素做法是用「刚走完的那个扇区」的时长外推下一个扇区。在扇区不等宽时这很差：
实测扇区 `[122, 155, 133, 116, 144, 149]` 拍，从 155 拍的扇区进入 116 拍的扇区时，
按旧速率外推到边沿只走了 45°，**跳变 15°** → `sin(15°) = 26%` 的电流落到 d 轴。

但 A1.1 同时测到那个模式**转与转之间重复到 1.5%**。所以改为记住**每个扇区上一转的时长**，
再用刚测完那个扇区的变化量去缩放速度——这样把「速度」（来自最新测量）
和「几何」（来自 per-sector 记忆）分开了：

```
predicted[k] = last_ticks[k] × (measured[k-1] / last_ticks[k-1])
omega = SECTOR_SPAN / predicted[k]        每个边沿一次除法，不是每拍
```

每个边沿一次除法在 24 电周期/s 下是 144 次/秒，M0 无硬件除法也毫无压力。

外推**永不越过下一个锚点**（钳位）。减速时越过锚点会让角度跑飞，而错的角度比旧的角度更糟——
它直接进 Park 变换。

### 验收对照

| 判据 | 阈值 | 实测 |
|---|---|---|
| 边沿处 θ 跳变 | < 10° | **max 1.24°，mean 0.21°**（10 个边沿） |
| 转速估计一致性 | 与 hall 计数差 < 3% | θ 斜率 **24.54** vs hall 计数 24.4，**差 0.5%** |
| θ 连续性 | — | 255/255 个采样点单调递增，每电周期一次回绕 |
| 6 个锚点间隔均匀 | 偏差 < 5° | **不满足**：53.6~68.1°，见 A1.1 |

**第三条不满足，且它的后果比「跳变」更隐蔽。** 均匀 60° 锚点在真实扇区不等宽时，
**锚点自身的角度就是错的**——真锚点角是各扇区宽度的累加，不是 `k × 60°`。
按 A1.1 的数字累加，锚点 2 偏约 **+10.5°**。边沿跳变小只说明外推**自洽**，
不说明角度**绝对准确**。

所以修正接口是**六项的 `MOTOR_ANGLE_ANCHOR_TRIM` 表**加一个全局 `MOTOR_ANGLE_OFFSET_Q16`
（两个物理来源不同：前者是锚点间距误差，后者是 hall 与电角零点的对齐）。
两者都留零，**由阶段 E 用 `id` 标定**——不把 A1.1 的时间数字烧进去，
因为那会用一个未知误差换掉一个已知误差。

### 顺带发现：反转起转不是 100% 可靠

五次里有一次反转起不来：`kick=0`、`fault=0`、`hall_changes` 不增、母线 0.255 A
（= 静态保持电流）。原因是 hall6 的 kick 是开环的，转子初始位置不巧时跟不上，
走满 40 步超时退出就留下一个静态保持。

已确认**不是新模块引起的**：`-DMOTOR_ADC=OFF -DMOTOR_ANGLE=OFF` 退回 A1 状态后同样能复现正常起转
（25.9 vs 25.1 电周期/s）。`hall6_regress.sh` 现在会用母线电流把「堵转」和「没驱动」区分开。

## 6. 阶段 E：FOC 接入与电流环闭合

### 入口条件

阶段 B / C / D 全部完成并验收。

### 做法

1. **先只跑 id/iq 观测，不闭环**：把 FOC 的 Clarke/Park 变换算出来记进 trace，
   电机仍由 hall6 驱动。检查 iq 是否与力矩正相关、id 是否接近 0。
   这一步能在不失控的前提下验证角度和电流标定是否自洽。
2. 再闭合电流环，输出 SVPWM。**起步用很低的 iq 目标**（对应约 0.3 A 绕组电流），
   确认能稳定运转后再逐步加大。
3. 保留 hall6 作为可切换的回退路径（`MOTOR_START_HALL6`），出问题能立刻退回已知可用状态。

### 验收

| 判据 | 阈值 |
|---|---|
| 开环观测阶段 id | 接近 0（说明角度对齐正确） |
| 电流环闭合后 iq 跟踪 | 阶跃指令的稳态误差 < 5%，无持续振荡 |
| 同等绕组电流下的转速 | 不低于 hall6 基线（FOC 应更优或至少相当） |
| 母线电流 | 与 `I_bus = D_eff² · V / R` 量级一致；异常偏大先查陷阱 1 和 VOUT 电容 |

### 必须先补的保护

**在加大电流之前**把保护接上，否则一次失控就烧板（3 号板已有过热史）：

- TIM1 BKIN（PA6，接 nFAULT）目前**被禁用**。F030 的 BKIN 复用与 F429 不同，
  之前尝试启用曾导致 MOE 锁死，需要重新确认 AF 与极性后再打开。
- 软件过流：用阶段 C 的电流采样做逐拍限幅，超阈值立刻关 MOE。
- 堵转检测：`openloop.c` 里已有 `OL_HALL_STALL_MS` 的思路可参考。

## 7. 阶段 F：负载动态性能摸底与优化

### 入口条件

阶段 E 电流环稳定；**且 0.5 的电源限流问题已解决**（否则测的是电源不是电机）。

### 先摸底，再优化

不要一上来就调 PI 参数。先把系统的实际能力量出来：

| 测项 | 方法 | 记录什么 |
|---|---|---|
| 电流环带宽 | iq 指令小幅方阶跃，trace 记 iq 响应 | 上升时间、超调、稳态误差 |
| **工作点增量电感** | 电流上升斜率 `di/dt = V/L` | 复核 1 kHz 下测得的 437 µH/相，饱和会使其下降（见 3.3） |
| 转速–力矩曲线 | 逐点加载，记录稳态转速与绕组电流 | 得到 `Kt` 与可用力矩范围 |
| 反电动势常数 `Ke` | 外部拖动电机，测开路相电压 | `Ke` 决定基速与弱磁起点，**阶段 G 必需** |
| 加速性能 | 空载从静止到目标转速 | 时间、峰值电流、是否撞限流 |
| 负载突变恢复 | 突加/突卸负载 | 转速跌落幅度与恢复时间 |
| 温升 | 长时间运行，记录板温与电流漂移 | 3 号板重点关注 |

### 优化顺序

1. 先修**结构性**问题（采样延迟、角度误差、死区补偿），再动控制参数。
   角度误差 5° 带来的力矩损失比 PI 参数微调大得多。
2. 电流环 PI 先按 `L/R` 时间常数解析设计，再实测微调。每相 `R = 0.65 Ω`、
   `L = 437 µH` 已实测（`τ = 673 µs`）；但那是 1 kHz 小信号值，
   要用工作电流下的电流上升斜率（`di/dt = V/L`）复核增量电感，饱和会让它变小。
3. 速度环在电流环稳定后再加，带宽至少差 5 倍。

### 验收

给出一份数据报告（放 `docs/report/`），包含上表全部测项的实测值、
测试条件（母线电压、电源型号与限流、环境温度）、以及原始 trace 数据路径。

## 8. 阶段 G：弱磁控制

### 入口条件

**阶段 F 完成，且必须已实测 `Ke` 和母线电压利用率。** 弱磁是在电压饱和之后才有意义的手段，
没有这两个数就无法判断该不该弱磁、以及从哪个转速开始弱磁。

**另一个前置条件是电流采样分辨率**（见 3.4 与待决项 0.3 #1）：弱磁靠精细调节负 `id`，
若 `id` 的分辨率是 80 mA/LSB，弱磁环会来回抖动，更危险的是可能**过冲进入不可逆去磁区**。
前端增益未解决时不要进入本阶段。

### 判断是否需要弱磁

弱磁只解决一个问题：**转速受母线电压限制**。判据是电压环节饱和——
即 SVPWM 的调制比已接近上限（`|Vd,Vq|` 达到 `Vbus/√3`）而转速仍需提高。

先算基速：`ω_base ≈ (Vbus/√3 − R·i) / Ke`。若目标转速低于基速，**不要做弱磁**，
去查力矩不足或负载问题。

### 做法

1. 在电压饱和后注入负 `id`（去磁电流），按 `id = −(...)` 的常规弱磁律，
   优先用简单的电压反馈式弱磁（用调制比饱和量做 PI 调 `id`），
   比查表式更鲁棒、也更容易在这套观测手段下调试。
2. **限幅必须先写好**：`|id|` 上限、`√(id² + iq²)` 总电流上限、以及退出条件。
3. 每次提高 `|id|` 都要小步，并同时看母线电流、绕组电流、温升。

### 风险（务必记录在报告里）

- **永磁体不可逆去磁**：`|id|` 过大且温度高时会永久损伤磁钢，损失不可恢复。
  必须设保守上限，并在升温后重测力矩常数确认没有退磁。
- **失控风险**：弱磁区若突然失去电流环控制（如复位、MOE 关断），
  反电动势可能高于母线，通过体二极管回灌母线，产生过压。
  进入弱磁前确认母线有足够的储能与钳位能力。
- 本实验装置**电源限流约 1.6 A**，弱磁工况电流更大，0.5 的问题在这里是硬阻塞。

### 验收

| 判据 | 阈值 |
|---|---|
| 弱磁投入后最高转速 | 明显高于实测基速 |
| 投入/退出过程 | 无转速突跳、无电流尖峰、无失步 |
| `|id|` | 始终在设定上限内 |
| 退磁检查 | 弱磁测试前后的 `Kt` 变化 < 5% |

## 9. 贯穿性要求

### 9.1 每次改动后跑回归

按 1.1 的命令复现 1.2 的期望值。**hall6 基线是唯一已知可用的状态**，
任何时候 FOC 出问题都要能退回它。

### 9.2 数据落盘

实测采数走 benchgate，session 落在 `<design>/models/captured/sessions/<id>/`；
本仓的分析产物放 `models/captured/`，报告放 `docs/report/`。
每份报告必须写清母线电压、电源限流设定、以及固件的 cmake 参数组合。

### 9.3 报告模板

每个阶段结束时提交：

```
阶段：<A/B/C/...>
固件参数：<完整 cmake -D 列表>
硬件条件：母线 __ V，电源限流 __ A，VOUT 电容状态：已拆除

验收判据逐条对照：<通过/不通过 + 实测值>
遗留问题：<列表>
```

### 9.4 cmake cache 陷阱

所有 `MOTOR_*` 参数都是 cmake cache 变量，**复用旧 build 目录会残留上次的值**。
切换参数组时先 `rm -rf build/Release`，或显式传全部相关选项。
本轮曾因此出现「传了 `RUN_DUTY=20` 但芯片上跑的是 12」的假象。

### 9.5 不要做的事

- 不要为了让测试通过而调高电源限流（见 0.5）。
- 不要把 VOUT 滤波电容装回去。
- 不要手改 `sim/codegen_stm32/` 下的生成代码。
- 不要用 SWD 调函数（`gdb call`）做实测验证——本轮实测不可靠，
  返回值正常但外设状态常对不上。用 `MOTOR_AUTO_START` 烧录后 reset 的路径。
- 不要在没有过流保护的情况下加大电流（见阶段 E）。
